Installing an addon puts it on the machine. **Enabling** it puts it in the session.
The two are separate, and the session is the one that decides.

## Enable a set

In `config/server.toml`:

```toml
[session]
addons = ["ironlark:examples", "you:doors"]
```

Enabling happens per addon, not per mod: an addon is the unit you install, share and
switch on. Selecting a gamemode and a map are separate choices from among what you
enabled.

## Order is load order

The list's order is the order addons load, and that is also the order mods are
initialised in. A mod that reacts to another's startup can rely on it. Reorder the
list and you reorder startup.

## The baseline is always on

`ironlark:core` is enabled in every session and cannot be switched off, so a session
always has a floor under it. You never need to list it, and forgetting it costs nothing.

Write it in full if you write it at all. Every entry is matched against the addon's whole
`author:addon` id, and a name that matches nothing refuses the session by name — `core`
alone is not an id, and a session listing it will not start.

## Three states, three intentions

| Written | Runs |
|---|---|
| no `addons` key | everything installed — nobody has curated this install |
| `addons = []` | the baseline alone — curated down on purpose |
| `addons = [...]` | the baseline plus exactly these, in this order |

<Aside type="caution">
An empty list and a missing key look similar and mean opposite things. The file can
say both, so say the one you mean.
</Aside>

## Naming something that is not installed stops the session

```
enabled addons are not installed: you:doors. Install them, or remove them from
the session's addon list
```

The whole resolution fails rather than quietly skipping the name. A session missing an
addon you asked for is not the session you configured, and finding that out from a
missing door an hour later is worse than not starting.

## Every player needs what the session runs

The host decides the set; a joining player runs what the host tells it. A player who
does not have an enabled addon is refused, and told which one.

There is no partial join, deliberately: the content they lack would simply be absent
from the world around them, and a player who cannot see the doors everyone else walks
through is in a worse state than one who was turned away.

So the set you enable is the set every player must install. Keep it small until you
have a way to hand people content.
